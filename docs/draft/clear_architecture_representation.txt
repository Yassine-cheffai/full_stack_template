Implementing Clean Architecture in FastAPI with SQLAlchemy means keeping your business logic (Services) completely decoupled from your framework-specific layers (Routers) and data-access layers (Models).

To do this properly, SQLAlchemy models should never leave the Service layer. Instead, the Service layer converts the database records into pure Pydantic models (DTOs / Data Transfer Objects) before returning them to the Router.


[ Client ]
│  ▲ (Pydantic Schema)
▼  │
[ Router Layer (API Endpoints) ]
│  ▲ (Pydantic Schema)
▼  │
[ Service Layer (Business Logic) ] <─── Converts SQLAlchemy model to Pydantic
│  ▲ (SQLAlchemy Entity)
▼  │
[ Database / Repository Layer ]

Why this implementation satisfies Clean Architecture:
Separation of Concerns: If you decide to drop SQLAlchemy later and move to an ODM like Motor (MongoDB) or raw SQL via asyncpg, your Router file remains completely untouched. You only have to update the database parsing inside services.py.

Safety: Because the service layer converts the data into a UserDTO, there is zero risk that the API layer accidentally exposes sensitive column fields (like hashed_password) down to the HTTP client payload response.
